# Стресс- и краш-тесты перед публикацией

Правило владельца с 23.11.2026: без этих проверок релиз не считается готовым. Результаты записываются в отчёт о публикации.

## Стресс (нагрузка)
- 1000 подряд `screenshot` и 1000 `left_click`: p95 времени ответа, ошибки, CPU и память процесса `wdpilot` (утечки по росту RSS).
- 100 MCP-запросов без ожидания ответа (очередь stdin): все ответы по своим id, без потерь.
- Окно 4K и Retina 2×: время снимка и размер PNG в пределах лимитов (≤1568 px, ≤1,15 Мп).

## Краш
- ОС: Windows 10/11, Ubuntu (X11 и XWayland), macOS arm64 и x64; один и два монитора, масштаб 100/150/200 %.
- Кривые данные: битый JSON, пустые и отрицательные координаты, координаты вне снимка, `text` 100 000 символов, неизвестные клавиши, лишние поля.
- Окно закрыто, свёрнуто, перемещено или изменило размер между снимком и кликом; окно перекрыто другим.
- Обрыв: клиент закрыл stdin посреди `type`/`hold_key`/`left_click_drag` — кнопки и клавиши отпущены, процесс завершился.
- Рестарт `wdpilot` во время сессии: клиент получает понятную ошибку, доступ нужно выдать заново.
- Двойные действия: повторный `select_window`, два `left_mouse_down` подряд, стоп во время `wait`.
- Стоп-клавиша и угол экрана во время каждого длительного действия.

Автоматизировано сейчас: `tests/e2e_linux.py` (часть краш-сценариев). Остальное добавляется на этапе 1.
